# Setti

A project chat for independent interior designers that keeps every dollar in sync with what was agreed: when a client changes their mind after money has already moved, one approval turns into the right PayPal actions (release a hold, capture less, refund minus the restocking fee, charge the difference), each tracked on its own.

> **Status: in development.** AI change drafts, designer pricing review, client confirmation and the PayPal Sandbox payment steps (authorize, capture, release, refund) are connected. The Alerts, Agents, Items and Procurement boards still show demo data. See [Sandbox evidence](#sandbox-evidence).

## Try it

Run `npm install`, then `npm run dev` and open `http://localhost:3000`.

Open **Quotes** in the sidebar, then select a quote example. The larger **Willow Residence** test quote is also available at `http://localhost:3000/quotes/willow`. **Quote V1** in the Maple chat still opens its original $1,500 payment example at `http://localhost:3000/quotes/maple`.

The report uses **AG Grid Community** for sorting, category and room filtering, search, pagination and a full-quote CSV export. Select an item's **Details** to inspect specifications, price sources and return terms. Totals are calculated from integer-cent line items and stay unchanged when filtering. Approved versions are read-only.

Willow has **28 lines: 22 products with IKEA US public reference prices checked on October 17, 2026, and six simulated design services**. Product details link to their official sources. Service rates, an 8.75% goods-only tax assumption and a single $99 delivery budget are test inputs, not supplier commitments or a location-specific tax calculation.

All project scopes, approvals and signatures are **demo data**. Maple's prices, return fees, $0 tax and delivery remain illustrative. Neither report confirms a client approval or PayPal payment, and opening a quote makes no payment calls.

## Sandbox evidence

`npm run sandbox:proof` runs one complete change through the app against the PayPal Sandbox, reads every PayPal resource back and writes the results to `evidence/` (see [probes/README.md](probes/README.md#app-level-proof)).

## What is here today

| Path | What it is |
|---|---|
| `src/ui/quotes/` | AG Grid approved quote report, available from the workspace, `/quotes/maple` and `/quotes/willow`. |
| `src/quotes/` | Typed Maple and Willow V1 examples and integer-cent quote totals, with validation and tests. |
| `src/db/` | Postgres schema (projects, items, quote revisions, revision lines, approvals) and test helpers. Database triggers freeze a revision once it is sent and only accept approvals that match its content hash. |
| `drizzle/` | SQL migrations generated by Drizzle, plus the hand-written quote-rule triggers. |
| `src/money/` | Pure money rules: what each change does to held or captured money, the over-capture allowance, the reauthorization window, refund promises, and a ledger snapshot. Amounts are integer cents. |
| `src/config/paypalEnv.ts` | Sandbox-only guard. Every PayPal client goes through it. |
| `probes/` | Scripts that record how the PayPal sandbox really behaves (partial captures, over-capture, reauthorization, vault, Pay Later, void). See [probes/README.md](probes/README.md). |

## Run the database

The local database runs in Docker (Postgres 17 on port 5433, see `docker-compose.yml`). It creates a separate `setti_test` database for tests.

```bash
cp .env.example .env.local   # the default DATABASE_URL and TEST_DATABASE_URL match docker-compose.yml
npm run db:up                # start Postgres and wait until it is healthy
npm run db:migrate           # apply migrations to the development database
npm run db:down              # stop it
```

After changing `src/db/schema.ts`, run `npm run db:generate` to create a new migration.

## Run the tests

```bash
npm install
npm run db:up     # needed for the database tests
npm test          # vitest; migrates the test database first
npm run typecheck # tsc --noEmit (includes the probes)
```

Database tests run only when `TEST_DATABASE_URL` is set. Without it they are skipped and the rest of the suite still runs.

## Run the probes

```bash
cp .env.example .env.local   # then fill in the sandbox app credentials
npx tsx probes/p1-standing-authorization.ts --label wallet-a
```

The probes print a buyer-approval link when a buyer step is needed and write their results to `probes/recorded/`.

## Sandbox only

This is a hackathon build. `PAYPAL_ENV` must be `sandbox`, and any base URL other than `api-m.sandbox.paypal.com` is rejected. No live PayPal account is ever used.

## Stack

Next.js (App Router) and TypeScript, Postgres with Drizzle, pg-boss for background jobs, the PayPal Server SDK, and the Anthropic SDK. Deployment target: Render.
